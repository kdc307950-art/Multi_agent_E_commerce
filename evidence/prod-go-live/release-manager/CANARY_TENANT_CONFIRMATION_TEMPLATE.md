# 首批真实租户书面确认函（模板）

> **用途**：正式生产上线**仅放行经书面确认的真实租户**。本模板用于向业务方/租户方征集**书面确认**。
> **红线（必须向租户方明示）**：
> 1. **本仓库仅提供模板与流程，不代签**；书面确认必须由**真人/业务方**签署（电子签章或手签+日期），存证留痕。
> 2. 退款 / 退货 / 改址**强制进入唯一 `human_approval` 人工审批**（仅本租户 `admin`/`approver` 可批，二次确认）；**无任何 direct 绕过**。
> 3. 所有资金与敏感操作**完全自托管**、**带租户边界**、**留审计**；跨租户访问默认拒绝。
> 4. 上线路径符合**先只读 + shadow 观察 → 人工复核 → 对账 → 业务负责人确认 → 指定租户切 live**，且上线后**连续观察 ≥7 天**。
> 5. 确认函签署后，一切账号/密钥交接以本函附件清单为准，责任边界以本函及《账号密钥交接与责任》为准。
>
> 依据：`deploy/records/CANARY_TENANTS-TEMPLATE.md`、`deploy/records/SCALEUP_APPROVAL-TEMPLATE.md`、
> `deploy/OPS_RUNBOOK.md` §1/§3、`AGENTS.md`（Agent 宪法）安全红线、`evidence/prod-go-live/release-manager/SHADOW_TO_LIVE_GATE.md`。

## 3. 人工审批承诺

我方（租户方）确认：**同意**本系统对退款/退货/改址强制实行**人工审批**，包括——
- 仅本租户内的 `admin` / `approver` 角色可审批；
- 审批需**二次确认**；审批记录 `approver` 身份用于**审计留痕**；
- 审批拒绝即终止，**绝不执行**；
- 跨租户审批/操作一律**拒绝并留痕**；
- 审批人/目标资源必须**同租户**（同 `tenant_id`）。

## 4. 账号密钥交接与责任

> **责任边界**：账号/密钥交接以本函附件 B 为准。默认责任划分见下。

| 项 | 责任方 | 说明 |
|---|--------|------|
| 登录凭据生成（argon2id/bcrypt PHC） | 系统运维方 | 明文口令由业务方线下安全交付，系统仅存哈希 |
| 生产数据库 / 备份密钥（`BACKUP_ENC_KEY`、`BACKUP_ROLE_PASSWORD`、DB 口令） | 系统运维方 | 服务器环境注入，**绝不落库/落日志/提交仓库** |
| 租户成员账号开通与角色授予 | 系统运维方（按本函附件 A） | 经受控迁移/运维脚本创建，`preview/production 禁用 seed_default` |
| 日常审批与业务操作 | 租户方（admin/approver/agent） | 依本函 §3 职责 |
| 资金/敏感操作最终责任 | 租户方 | 系统保障无绕过/无重复/可对账，但资金决策最终由租户方负责 |
| 账号/密钥变更、停用、删除（被遗忘权） | 系统运维方 + 租户方 | 按租户范围执行并留痕 |

**交接动作（由系统运维方执行并留痕）**：
1. 用受控迁移/运维脚本创建租户与成员（`scripts/create_bootstrapped_tenants.py` 等），生成 argon2id/bcrypt PHC 写入 `AUTH_LOGIN_CREDENTIALS`。
2. 将租户 ID 加入 `LAUNCH_ALLOWED_TENANTS`（注入 `deploy/.env.<env>`，`check_secrets` 校验必要项非空/非占位）。
3. 为成员授予相应角色（customer/agent/admin/approver）；审批人须为该租户 admin/approver。
4. 记录审计/留痕：操作者、审批依据（本函编号）、时间、结果。

## 5. 上线与观察承诺

租户方确认：
- 接受**先只读 + shadow 观察 → 人工复核 → 对账 → 业务负责人确认 → 指定租户切 live** 的受控门控（见 `SHADOW_TO_LIVE_GATE.md`）。
- 切 live 后**连续观察 ≥7 天**；观察期内关注跨租户拒绝、重复执行、回调失败、人工介入率、对账差异、错误率、备份结果。
- **任何资金异常，系统将立即关 live 转人工**，租户方应配合处置。
